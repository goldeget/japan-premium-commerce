# 프로젝트 아키텍처 및 현재 브랜드 기준

## 확정된 플랫폼

- PrestaShop 공식 안정 버전 9.2.0, Hummingbird v2.1.2, MariaDB 10.11을 사용한다.
- PrestaShop 코어와 Hummingbird 부모 테마는 수정하지 않는다. 기능은 독립 모듈, 자식 테마, Compose 및 CI 설정으로 구현한다.
- main은 기준 상태로 보존하고 모든 개발 변경은 work에서 작은 체크포인트로 저장한다.

## 브랜드와 법인 경계

- 현재 고객용 개발 브랜드는 ORDENOWA다. 공식 표기는 일본어 オーデノワ, 영어 ORDENOWA, 한국어 오데노와다.
- 일본어 설명은 法人向け商品調達・受発注サービス, 슬로건은 企業と商品をつなぐ、次世代のB2B調達プラットフォーム다.
- KURANEA는 과거 개발 브랜드와 기존 기술 경로로만 보존한다. 현재 고객 화면에 KURANEA 명칭이나 이미지를 표시하지 않는다.
- 공식 ORDENOWA 원본은 확인 가능한 첨부 파일을 assets/brand/source/에 그대로 보존한다. 파일 접근이 불가능한 동안 이미지를 재제작하거나 KURANEA 이미지로 대체하지 않는다.
- LOGISTEED, Ltd. 정보는 편집 가능한 기업 참조정보다. 실제 판매 법인, 판매 책임자, 고객센터, 은행 계좌, 정책, 승인 상태를 별도로 관리한다. 참조정보만으로 LOGISTEED 공식 판매처라고 표시하거나 실거래를 켜지 않는다.

## PrestaShop 구성

- themes/kuranea는 기존 경로를 보존한 Hummingbird 자식 테마다. 기술 경로가 KURANEA여도 고객 표시는 ORDENOWA 설정을 사용한다.
- modules/kuraneapostcode는 일본우편 공식 KEN_ALL 기반 배송지 자동검색을 제공하고 선택 주소를 PrestaShop 네이티브 주소 필드에 저장한다.
- modules/kuraneabackoffice는 한국어 관리자 번역 보완을 제공한다. 코어 번역/소스는 직접 덮어쓰지 않는다.
- modules/kuraneabusinessprofile은 한국어 쇼핑몰 운영 설정과 브랜드·법인 참조·판매 운영정보를 관리한다. 기존 모듈 경로는 호환을 위해 유지한다.

## 운영정보 관리 모듈

- 쇼핑몰 이름, ja/en/ko 브랜드명, 슬로건, 로고·favicon·PWA·OG 자산, 법인 참조정보, 실제 판매자, 책임자, 고객센터, 은행 계좌, 결제·배송·반품·환불, 약관·개인정보·특정상거래법, SEO·PWA 정보를 버전 관리한다.
- 초안 저장, 관리자 전용 미리보기, 게시, 변경 이력과 이전 버전 복원을 지원한다. 각 스냅샷은 변경자·시각·복원 출처를 보존하고 복원은 새 초안을 만든다.
- 은행 계좌는 별도 관리자 권한으로 보호하며 일반 설정, 미리보기, 이력에는 전체 정보를 표시하지 않는다. 권한 없는 버전 복원이 은행 계좌를 변경하지 못하게 한다.
- 회사 참조정보와 실제 판매사업 정보를 분리한다. 판매자 승인과 외부 운영 승인 신호가 확인되기 전 판매자 표시·checkout·결제·실거래를 비활성화한다.
- 고객 화면, 이메일, SEO 메타데이터, manifest는 게시본만 사용한다. 초안은 관리자 미리보기에서만 볼 수 있다.
- 이미지 업로드는 원본과 버전을 보존하고 형식, 크기, MIME, 해상도를 검증한 뒤 파생 이미지를 생성한다. 파일 접근이 막힌 동안 공식 로고 작업은 차단한다.

## 언어·PWA·개인정보

- 고객 쇼핑몰은 일본어 기본, 영어·한국어를 지원한다. 관리자 화면과 신규 운영 설정 모듈은 한국어로 제공한다.
- PWA 메타데이터는 게시된 브랜드 설정을 사용한다. 공식 이미지가 없으면 임의의 그림 대신 텍스트 이름을 표시한다.
- 서비스 워커에는 공개 정적 자산만 캐시한다. 계정, 고객정보, 장바구니, 결제, 주문, 은행 잔액과 운영 비밀정보는 저장하지 않는다.

## 개발 및 완료 게이트

1. 변경 전 로컬 상태와 원격 work·main SHA를 확인하고 미커밋 파일 및 named volume을 보존한다.
2. 권한, 저장·게시·복원, asset 검증, 공개 연동을 단위·통합 테스트로 확인한다.
3. 격리 CI에서 모듈 설치, DB 스키마, 관리자 흐름과 다국어 고객 화면을 검증한다.
4. 실제 브라우저/PrestaShop 검증을 수행하지 못한 항목은 PASS로 표시하지 않는다.
5. 기능 단위로 커밋·푸시하고 원격 SHA와 커밋 파일을 다시 확인한다.
