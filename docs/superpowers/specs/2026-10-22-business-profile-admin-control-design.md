# 쇼핑몰 운영정보·브랜드 관리자 제어 설계

- 작성일: 2026-10-22
- 대상 저장소: `goldeget/japan-premium-commerce`, `work`
- 상태: 사용자 설계 승인 완료·구현 진행 중
- 프로젝트 기반: PrestaShop 9.2.0, Hummingbird 2.1.2

## 1. 목표

운영자가 한국어 Back Office에서 쇼핑몰 브랜드, 회사 참조정보, 실제 판매자 정보, 고객센터, 은행 계좌와 결제 안내, 배송·반품·환불 정책, 이용약관·개인정보 처리방침, 일본 특정상거래법 표시사항, SEO 및 PWA 메타데이터를 등록·수정·저장·미리보기·게시·복원한다. 고객 화면, 이메일, 알림, 검색 메타데이터 및 PWA는 하나의 게시 버전을 재사용한다.

최종 브랜드명은 영문 `ORDENOWA`, 일본어 `オーデノワ`, 한국어 `오데노와`로 확정됐다. 일본어 설명은 `法人向け商品調達・受発注サービス`, 슬로건은 `企業と商品をつなぐ、次世代のB2B調達プラットフォーム`이다. 기존 KURANEA는 과거 개발 브랜드이며 고객용 공식 브랜드가 아니다. 기존 KURANEA 이미지 원본과 Git 이력은 보존한다.

2026-10-22에 첨부된 `ORDENOWA_DEPLOYMENT_BRAND_PACK_20261022.zip`에서 승인된 원본 3종과 파생 이미지 17종을 확인했다. 원본·파생 파일의 크기와 SHA-256은 `assets/brand/ordenowa/asset-manifest.json`에 기록하고 `tests/smoke/test_ordenowa_brand_pack.py`로 검증한다. 고객용 ORDENOWA 파생 이미지가 준비됐으며 기존 KURANEA 원본은 별도 백업으로 보존한다.

LOGISTEED, Ltd.의 회사 개요는 변경 가능한 참고정보로 관리하며, 실제 판매사업자와 LOGISTEED의 관계·운영 승인 상태를 별도로 확인한다. 승인 확인 전에는 ORDENOWA를 개발·격리 테스트에서 사용할 수 있으나 고객에게 LOGISTEED의 공식 판매처라고 표시하거나 production 판매·결제를 활성화하지 않는다.

## 2. 현재 저장소에서 확인한 구조

- `docs/KURANEA_MASTER_DEVELOPMENT_DIRECTIVE.md`의 회사·법정 표시사항 절은 야마토 운수를 운영 법인으로 서술한다. 새 운영 기준을 별도 문서로 기록하고 이 절은 현행 기준에서 제외한다. 과거 문서와 Git 이력은 삭제하지 않는다.
- KURANEA를 최종 브랜드로 서술하는 기존 문구는 과거 개발 기준으로 보존하고, 이 승인 문서를 신규 변경의 현행 기준으로 사용한다.
- `modules/kuraneabackoffice`는 관리자 언어·로그인 지원을 담당하며 운영정보 저장 기능은 없다.
- 자식 테마의 head/manifest 및 footer 모듈 오버라이드는 KURANEA 이름과 정적 브랜드 자산을 직접 참조한다. 이메일과 법적 표시 화면에 대한 단일 운영정보 공급자는 아직 없다.
- LOGISTEED 공식 페이지는 조사 시 HTTP 403을 반환했다. 회사명·번호·주소·대표전화는 사용자가 제공한 참조값으로 초기 등록하며, 소스 URL과 현재 검증 상태를 함께 보존한다.

## 3. 권장 아키텍처

### 3.1 전용 모듈

`kuraneabusinessprofile` 모듈을 추가한다. 모듈명은 내부 기술 식별자이며 고객 화면에 노출하지 않는다. 모듈은 데이터 모델, 한국어 관리자 메뉴 `쇼핑몰 운영 설정`, 권한, 게시 검증, 미리보기, 변경 이력과 복원을 소유한다. PrestaShop 코어는 수정하지 않는다. 기존 `kuraneabackoffice`는 로그인/번역 지원 용도로 유지한다.

관리자 화면은 설정을 다음 섹션으로 나눈다: 기본 정보, 브랜드·로고, 사업자 정보, 고객센터, 은행 계좌, 결제 설정, 배송 설정, 반품·환불, 이용약관, 특정상거래법 표시, 다국어, SEO·PWA. 전체 UI와 검증 오류는 한국어로 표시한다. 직원 권한으로 일반 정보 편집, 은행 정보 편집, 게시, 이력/복원 동작을 분리한다.

### 3.2 단일 원본과 버전

모듈 전용 DB 저장소를 게시 가능한 단일 원본으로 사용한다. 버전 레코드는 shop 범위, 상태(draft/published), locale별 콘텐츠, 수정자·시각, 게시자·게시 시각을 가진다. 초안 저장은 새 변경 버전을 만들고, 게시 시 공개 버전 포인터만 원자적으로 바꾼다. 변경 이력은 이전/신규 프로필 버전을 참조하고, 관리자 화면에서 바뀐 항목별 이전값과 신규값을 비교한다. 복원은 과거 데이터를 덮어쓰지 않고 그 버전을 새 초안으로 복사한 다음 게시 절차를 다시 거친다.

PrestaShop의 `PS_SHOP_NAME` 등 코어가 요구하는 값은 호환 어댑터가 게시 시점에 동기화한다. 독립적으로 수정 가능한 두 번째 원본으로 두지 않는다. 테마·CMS·메일·SEO·PWA는 모듈의 locale-aware `PublishedProfileProvider`를 통해 같은 게시 버전을 읽는다.

### 3.3 프로필 구분과 기본 상태

프로필은 다음 경계를 갖는다.

1. **브랜드**: 일본어 `オーデノワ`, 영어 `ORDENOWA`, 한국어 `오데노와`; 일본어 설명 `法人向け商品調達・受発注サービス`; 슬로건 `企業と商品をつなぐ、次世代のB2B調達プラットフォーム`; 데스크톱/모바일 로고, 파비콘·Apple Touch·PWA 아이콘, OG 이미지와 이메일 로고의 승인 파생 자산을 사용한다. 승인된 원본과 파생 파일의 무결성은 manifest 계약 테스트로 확인한다.
2. **회사 참고정보**: ロジスティード株式会社, LOGISTEED, Ltd., 법인번호 `4010001226242`, `〒104-8350 東京都中央区京橋二丁目9番2号 ロジスティードビル`, 회사 대표전화 `03-6263-2800`, 대표자 `中谷 康夫`, 공식 참조 URL `https://www.logisteed.com/jp/profile/outline/`, 검증 상태.
3. **판매사업 프로필**: 실제 판매 법인, 판매 운영 책임자, 판매사업 주소/전화/이메일, 고객센터 연락처, 결제·배송·반품·환불 정책 및 특정상거래법 필드.
4. **콘텐츠**: 회사소개, 주문·결제 안내, 이용약관, 개인정보 처리방침, 고객 알림 등 locale별 문안과 SEO 메타데이터.

회사 개요의 대표전화는 쇼핑몰 고객센터로 자동 복사하지 않는다. 회사 참고정보는 `user-provided reference` 상태이고 판매사업 관계 승인은 `pending`이다. 브랜드명과 문구는 사용자 확정값으로 등록하지만, 공식 이미지 업로드 전에는 이미지가 필요한 공개 슬롯을 비워 두며, 판매자 승인 전에는 판매 프로필 게시와 고객 거래를 비활성으로 둔다. 판매 책임자, 고객센터 전용 연락처, 은행 계좌와 정책은 확인 전까지 비워 둔다. 임의 정보를 채우지 않는다.

### 3.4 초안·미리보기·게시 제어

관리자는 초안을 저장하고 인증된 미리보기 URL로 locale별 고객 화면을 확인한 뒤 게시할 수 있다. 미리보기는 `noindex` 처리하고 현재 게시 버전을 변경하지 않는다. 게시 검증은 다음을 요구한다.

- 판매 법인 관계 및 판매사업 운영 승인이 권한 있는 관리자를 통해 명시적으로 확인됨.
- 법정 판매자 필수 항목과 고객 연락처가 입력됨.
- 결제·배송·반품/환불 및 필수 약관이 일본어·영어·한국어로 준비됨.
- 공개 브랜드 이름이 승인되고 필수 공식 로고/아이콘 세트가 업로드·검증됨.
- 공개할 은행 계좌가 선택된 결제 방식과 연결되며 권한 검사를 통과함.

누락되거나 승인 대기 중인 필드는 관리자에게 한국어 검증 메시지로 표시한다. 승인 확인은 권한 있는 직원의 상태 변경과 자동 이력으로 남기며 증빙 파일 업로드를 요구하지 않는다. 미게시 프로필로 공식 판매처 주장이나 판매자 법정 표시를 공개하지 않는다. production의 결제/주문 활성화도 게시 승인 상태를 검사한다. 개발·CI 환경은 격리 테스트 프로필로 별도 검증한다.

### 3.5 브랜드 자산 업로드와 복구

업로드는 관리자 세션·권한·CSRF를 확인하고 PNG/JPEG/WebP만 허용하고, 10 MiB 이하 및 각 변 1–8192px 범위의 파일 크기, MIME, 실제 디코딩을 검증한다. SVG와 임의 실행 가능 형식은 입력에서 제외한다. 원본은 비공개 버전 경로에 보존하고 웹용 파생물만 공개 경로에 버전별 저장한다. 이미지 처리기는 투명 여백 정리, 데스크톱/모바일 로고, favicon, Apple Touch Icon, 192/512/maskable PWA, OG 크기를 만든 뒤 관리자 미리보기를 제공한다.

게시 버전 변경 시 새 버전의 정적 URL과 service worker cache revision을 사용해 이전 이미지가 잔류하지 않게 한다. 기존 KURANEA 원본과 현재 파생 파일은 백업으로 유지한다. 복원은 이전 자산 세트를 새로운 초안 버전에 다시 연결한다.

### 3.6 공개 화면 연동

- 테마 head/header/footer는 같은 공급자에서 브랜드명, 로고, OG, favicon, manifest 이름/아이콘을 읽는다.
- 회사소개, 고객센터, 결제 안내, 배송, 반품/환불, 이용약관, 개인정보 및 `特定商取引法に基づく表記`는 locale별 게시 콘텐츠를 렌더링한다.
- PrestaShop 메일의 기본 shop name 호환 동기화와 주문/고객 알림의 운영정보 변수 공급을 별도 어댑터로 구현한다. PrestaShop 9.2.0에서 사용할 공식 hook/API는 구현 단계에서 원본으로 확인한다.
- PWA manifest는 게시 프로필에서 동적으로 구성한다. service worker는 공개 정적 자산만 캐시하고 계정·장바구니·결제·주문·고객 데이터를 캐시하지 않는다.
- ORDENOWA 명칭과 이미지 원본은 승인된 개발 브랜드 자산이다. 공식 파생 이미지가 고객용 브랜드 설정의 기본 자산으로 연결돼 있으며, 관리자는 한국어 운영 설정에서 교체 이미지를 업로드·미리보기·게시할 수 있다. KURANEA 자산은 legacy 백업으로 보존하며 ORDENOWA 고객 페이지에서 사용하지 않는다. LOGISTEED 판매사업 승인 전에는 공식 판매 관계 주장·production 결제·판매를 차단한다.

## 4. 보안·감사

모든 변경은 PrestaShop 직원 권한, CSRF, 입력 검증, 출력 escape를 거친다. 은행 계좌 편집과 변경 이력 열람은 별도 권한을 둔다. 이력은 변경자, 시각, 이전/신규 버전을 기록한다. 일반 이력 보기에서는 계좌번호를 마스킹하고, 계좌 권한이 있는 관리자만 이전값을 열람·복원한다. 복원은 권한 있는 관리자만 실행한다. 로그에는 계좌번호와 비밀정보를 쓰지 않는다. 운영 비밀정보는 저장소, CI 출력, 공개 GitHub 파일에 넣지 않는다. 실제 운영 DB와 named volume에는 테스트 데이터를 넣지 않는다.

## 5. 초기 데이터와 이행

- LOGISTEED 회사 개요의 사용자 제공 참조값(법인명, 영문명, 법인번호, 주소, 대표전화, 대표자 `中谷 康夫`)을 편집 가능한 `회사 참고정보` 초안에 넣고, 소스 URL 및 검증 상태를 표시한다.
- 야마토 정보는 새 판매자 프로필로 복사하지 않는다. 이전 문서는 보존하되 현재 기준 문서가 우선함을 명시한다.
- ORDENOWA 확정 이름, 현지화명, 설명, 슬로건 및 manifest로 검증된 공식 파생 이미지의 기본 경로를 프로필에 등록한다.
- 기존 KURANEA 이름/로고는 legacy 백업으로 보존하고 ORDENOWA용으로 연결하지 않는다.
- 현재 storefront 설정을 초안 프로필로 가져오되 원본 설정, 이미지, CMS 콘텐츠를 삭제하지 않는다. 운영 DB migration은 비파괴·멱등 방식이어야 한다.

## 6. 검증 계획

단위/통합 테스트는 프로필 검증, locale별 조회와 fallback, 권한 분리, CSRF, 게시 차단 조건, 버전 이력, 복원, 이미지 MIME/크기 검사, 파생 자산 생성과 service worker cache revision을 확인한다. 모든 동작 테스트는 GitHub Actions의 별도 Compose project와 빈 CI DB에서 수행한다.

실제 브라우저 QA는 CI 관리자 계정과 명시적 TEST 값만 사용한다. 다음 흐름을 PC·모바일에서 확인한다: 사업자 참고정보와 테스트 판매자/브랜드 수정 → 초안 저장 → 미리보기 → 게시 → 일본어·영어·한국어 메인/푸터/회사소개/특정상거래법/결제·배송·환불/메일·알림/SEO/PWA 확인 → 변경 이력 확인 → 이전 버전 복원 → 고객 화면과 아이콘 회귀 확인. 실제 LOGISTEED 판매 승인, 실제 은행 계좌/연락처와 정책은 운영자가 확인하기 전까지 fixture로만 시험한다.

## 7. 제외 범위와 안전 조건

이 설계는 LOGISTEED와 ORDENOWA의 실제 계열·위탁·판매 승인 사실을 확인하거나 법률 검토를 대체하지 않는다. 실제 판매 운영 책임자, 고객센터 전용 연락처, 은행 계좌, 결제·배송·반품 정책 및 법정 문안이 확정되기 전에는 공식 판매자로 공개하거나 운영 매출을 받지 않는다. ORDENOWA 승인 원본과 파생 이미지는 저장소에 반영돼 있으며, 실제 production 공개와 판매 활성화는 운영 승인을 받은 뒤 진행한다.

## 8. 수용 기준

1. 관리자는 한국어 `쇼핑몰 운영 설정`에서 모든 지정 항목과 ja/en/ko 문안을 코드 수정 없이 관리한다.
2. 초안 저장, 미리보기, 필수값 검증, 권한 제한, 게시, 변경 이력, 이전 버전 복원이 작동한다.
3. 회사 참고정보, 실제 판매자, 고객센터 연락처, 쇼핑몰 브랜드가 별도 필드와 명시적 상태를 가진다.
4. 게시된 동일 버전이 storefront, legal/CMS, checkout 안내, 이메일/알림, SEO, manifest와 PWA 아이콘에 반영된다.
5. 승인 대기 상태에서는 회사와 쇼핑몰의 공식 판매 관계를 외부에 주장하지 않고 production 주문/결제가 활성화되지 않는다.
6. 이미지 교체 기능은 검증·미리보기·파생 파일·이전 버전 복구를 제공하며 기존 KURANEA 원본은 보존한다. 승인된 기본 이미지의 무결성은 manifest와 격리 CI에서 확인한다.
7. 실제 고객 화면 QA는 격리 CI 데이터로 수행하고, 결과와 PC·모바일 증거를 저장한다. DB 값만 확인한 결과를 화면 반영 PASS로 처리하지 않는다.
