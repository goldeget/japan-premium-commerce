# ORDENOWA PWA Web Push Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development when executing this plan. Work in the existing `work` branch/worktree. Preserve all pre-existing untracked files and do not modify `main`.

**Goal:** Add an authenticated, revocable Web Push subscription foundation and safe synthetic push handling without sending to real customers.

**Architecture:** A dedicated `kuraneapush` PrestaShop module owns consent configuration, encrypted subscription persistence, customer account controls, and same-origin CSRF-protected mutation endpoints. The existing root service worker receives bounded event enums and produces fixed-route generic notices; it does not cache private pages. CI uses synthetic data and a no-network fake sender/event harness.

**Tech Stack:** PrestaShop 9.2/PHP module, MariaDB, Smarty, JavaScript service worker, existing Python/Node/Actions tests.

**Spec:** `docs/superpowers/specs/2026-10-26-pwa-push-design.md`

## Global Constraints

- Use the authenticated PrestaShop customer/shop context; never trust a client customer ID.
- Mutation requests are POST-only and require an explicit `Tools::getToken('kuraneapush', $context)` comparison plus same-origin validation, regardless of the global PrestaShop token toggle. In PrestaShop 9.2 the string argument is a page namespace and is purpose-bound.
- Browser permission is distinct from app consent. Request permission only in an explicit user action. Empty seller-approved notice copy disables subscription.
- Encrypt endpoint, `p256dh`, and `auth` together at rest with authenticated encryption using `ORDENOWA_PUSH_STORAGE_KEY` (base64-encoded 32 random bytes); bind shop/customer/digest as AEAD associated data and derive a separate HMAC key for endpoint identity. A shop-wide unique endpoint digest may not be transferred to a different customer. Scope every read/delete by current customer. Missing/malformed key configuration disables new subscriptions. Never expose or log those values. CI creates a throwaway per-run value.
- Apply consent copy, storage-key, and sender readiness checks only to subscribe. Revocation for the authenticated owner must remain available after those conditions disappear.
- Push payloads contain only an allowlisted event enum and locale. Localized text is fixed in code; destinations are fixed same-origin account routes. Reject arbitrary strings/URLs and oversized payloads.
- Preserve service-worker private-route/cache/logout protections. Never cache account/order/cart/subscription responses.
- CI uses synthetic records and a local sender/event harness that cannot make outbound network requests. Browser QA must not call the real browser push provider. No production credentials, real customer notifications, or customer PII.
- Admin controls and feedback are Korean-first; consent UI supports Japanese, English, and Korean. Consent body fields start empty.
- Do not report provider-backed push, support-event integration, or physical iOS/Android delivery as complete.
- Do not run Docker builds in Codex Cloud; Docker/DB/Chromium validation belongs in the isolated GitHub Actions workflow.
